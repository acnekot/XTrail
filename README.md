# XTrail · X 足迹

适用于 X（`com.twitter.android`）的 LSPosed 模块，目前适配 **12.37.2**。

- **固定底部导航栏**：滑动时底栏不再隐藏。
- **足迹**：把浏览过的推文记录下来，作为「歷史記錄」页里和「書籤」「喜歡」并列的第三个标签，卡片和交互沿用 X 原生的样式。
  - 按小时 / 按天 / 不分组，分组标题可点击折叠展开（默认展开），滚动时标题固定在标签栏下方。
  - 按页面类型（首页、搜索、主页、通知、列表、社群、详情等）和时间范围筛选，支持搜索。
  - 折叠到底时显示「没有更多的历史记录」。
- **设置页**：风格与 X 自带设置一致，带页面切换动画。入口有两个：
  - 手机桌面的 XTrail 图标（会打开 X 并直接弹出设置页）。
  - 「歷史記錄」→ 足迹 → 点开筛选面板 → 设置。

## 使用

1. 安装 APK，在 LSPosed 中启用 XTrail，作用域勾选 **X**（`com.twitter.android`）。
2. 强制停止 X 后重新打开。
3. 进入 X 的「歷史記錄」，右侧会出现「足迹」标签。点已选中的标签打开筛选面板。

### 桌面图标的系统确认

桌面图标通过显式 Intent 打开 X。部分系统（例如 MIUI/HyperOS）会弹出「XTrail 想要打开 X，是否允许？」，选「始终允许」后以后就不再询问。

### 设置项

| 设置 | 说明 |
| --- | --- |
| 固定底部导航栏 | 修改后需重启 X 生效 |
| 记录足迹 / 记录的页面类型 | 总开关，以及按页面类型单独开关 |
| 分组方式 | 按小时 / 按天 / 不分组 |
| 最多保留条数 | 200 / 400 / 1000 / 3000 |
| 清空足迹 | 删除全部记录，不可恢复 |

数据保存在 X 自己的私有目录里（`filesDir`、`xtrail_settings`），不上传、不联网。

## 构建

Windows + Git Bash，需要 Android SDK（build-tools 35.0.0、platform android-36）和 JDK 17 以上：

```bash
bash build.sh
```

产物为 `build/XTrail-debug.apk`。首次构建会自动生成 `debug.keystore`（已在 `.gitignore` 中），不要把自己的签名密钥提交进仓库。

## 实现说明

- 使用现代 Xposed API（libxposed 101/102），模块入口 `XTrailModule`，元数据在 `meta/META-INF/xposed`。
- X 是 R8 混淆的 Compose + Decompose + URT 时间线应用，下面的类名只对 12.37.2 有效，换版本需要重新定位：
  - 劫持原生「喜歡」之后的标签页状态（`com.x.navigation.y9`、`com.x.urt.b2`），把缓存的帖子条目喂给原生时间线，所以卡片是原生的。
  - 分组标题是插入列表的 `UrtTimelineLabel` 条目；折叠箭头和固定标题是叠在 Activity 上的 View，位置来自对 `LazyListState` 的测量回调。
- 模块不引用 X 的任何源码或资源。
- 模块 App 与 X 互相不可见（包可见性），模块没有 root 也进不了 X 的沙盒，所以设置页放在 X 进程里，桌面图标只负责拉起 X。

## 已知限制

- 只适配 X 12.37.2，其他版本大概率需要重新适配。
- 折叠状态不会记住，重新进入页面会重置。
- 小数据量下测试较多，3000 条上限时的滚动性能没有专门测过。
- 浅色主题下的外观没有充分测试。
